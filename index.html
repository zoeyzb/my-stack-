website building toolkit

How I make websites look expensive without starting from zero.

Pick the vibe, borrow compatible building blocks, give them to GPT, customize them, then add motion or real 3D only where it helps.

Copy → customize → connect → animate → ship.

Use the filters below. Every card tells you what it is, why I use it, and when I would not bother installing it.

01Find the vibe

Pinterest or a website I like. Copy the direction, not someone’s protected page pixel-for-pixel.

02Grab structure

21st.dev, shadcn, Aceternity, Magic UI or React Bits.

03Give it to GPT

Use this component; change it to my brand; keep this interaction; connect my real content/data.

04Add motion

Motion for normal UI. GSAP for cinematic timelines. Lenis only if smooth scrolling helps.

05Add real 3D

Three.js + React Three Fiber + Drei when 3D genuinely improves the experience.

06Ship

GitHub → test mobile/forms/errors/payments → Vercel frontend + Railway backend workers.

My rule: do not install everything. A normal landing page may only need shadcn + Motion. A cinematic page may earn GSAP. Real interactive 3D is when Three.js/R3F/Drei finally earn their weight.

Recover Scraper

Find HVAC/plumbing/home-service businesses—especially businesses without a proper owned website—then turn the good leads into personalized outreach and website sales.

1
SearchRailway controllers/workers search maps and public business sources.
2
FilterKeep HVAC/plumbing/heating/cooling. Throw away irrelevant categories.
3
Website checkFacebook/Yelp/profile pages do not count as a real owned website.
4
Store + dedupeDatabase/Redis remembers machine data; Sheets shows a readable human list.
5
Draft + sendGPT writes personalized outreach; Telnyx SMS or an iMessage/BlueBubbles path can deliver it.
6
SellShow a website preview → track replies → Stripe checkout → delivery workflow.

What is really running

The live Railway architecture has controllers, many acquisition workers, Maps/Gosom services, crawlers/scrapers, Redis, Google Sheets sync, SMS configuration and a Recover MCP gateway.

Why GPT matters

If Railway/GitHub/Sheets are connected, GPT can inspect them directly. If a local tool is not connected, GPT can write the Terminal command, you run it, then paste the result back.

Reply tracking

A real outreach system needs interested/no/follow-up/replied states—not just a giant “sent” count.

Database vs Sheets

Sheets is for eyes. The database is better for identity, dedupe, scale and automation.

Polymarket MCP

A market-intelligence stack: live data comes in, the scanner tests whether an apparent opportunity survives real order-book depth, history is saved, and GPT gets structured evidence to analyze.

1
Market dataGamma + CLOB market/rule/order-book data.
2
ScannerContinuous opportunity and structure scan on Railway.
3
Depth testWalk real asks and subtract an execution buffer rather than trusting a headline price.
4
HistoryNeon Postgres stores observations, resolved outcomes and calibration data.
5
Research packetRules, order books, price regimes, history and outside evidence.
6
GPTExplain what the evidence says and surface markets worth attention.

Railway split

The active architecture includes scanner, streams, history, maintenance and production services. Older brain/MCP services may be retired or sleeping.

Wallet + auto trade

That is a separate permission level. Paper trading, hard risk limits, logs, kill switches and human approval should come before real-money automation.

Website Factory

Do not start with “make me a website.” Start with a reference, a real goal, compatible components and a deployment path.

1
ReferencePinterest, a site I like, 21st.dev, Aceternity or an open-source template.
2
SpecWho is it for? What should people click, buy, book or understand?
3
ComponentsReact/Next + shadcn + compatible copy/paste libraries.
4
Motion / 3DMotion, GSAP, Lenis, optional R3F/Three.js/Drei.
5
BackendRailway + Supabase/Neon + Stripe if the product needs them.
6
ShipGitHub saves → test → Vercel deploys the frontend.

Upwork + Funding Outreach

Same automation pattern: find the right opportunity, verify the fit, personalize, draft, human-check the sensitive step, then track what happened.

1
FindRelevant job, donor, nonprofit, fund, company or person.
2
VerifyRead the brief/site and confirm the opportunity is actually relevant.
3
PersonalizeOne real reason this recipient/job fits.
4
DraftGPT writes a specific proposal/email instead of a generic blast.
5
ApproveYou check claims, price, attachments and sensitive sends/submissions.
6
TrackSent → reply → follow-up → won/no/closed.

Upwork

Browser automation should have secure auth handling, retries, rate limits, logs and human confirmation before actual submission.

Funding email

Gmail can be connected so GPT can research, draft and follow up, but outreach should remain tailored instead of identical spam.
